# Friday Activity Dashboard

เพิ่มวันที่ 14 กันยายน 2569 ใน `Graph_RAG/frontend` ที่ `/dashboard/friday-activities`
เป็นโมดูลที่ 6 ของ Dashboard ใช้ login, ธีม, เมนู และระบบบันทึกทดลองเดิมร่วมกัน
งานนี้ครอบคลุม Dashboard; ไม่เพิ่ม Planner หรือ NextPlus

## การใช้งาน

- เลือกปีการศึกษาและเทอม ดูทะเบียนกิจกรรม ค้นหาชื่อ บริษัท ศาสตร์ สถานที่ หรือหมายเหตุ
- กรองบริษัท รูปแบบ สถานะ และเฉพาะรายการต้องติดตาม พร้อมเก็บตัวกรองใน URL
- ดูบริษัทในเทอมที่เลือก แยกจำนวนจัดแล้ว รอจัด และยกเลิก กดบริษัทเพื่อกรองทะเบียน
- เปิดรายละเอียดและแก้ชื่อ รายละเอียด ศาสตร์ รูปแบบ วันเวลา สถานที่ สถานะ จำนวนคน ลิงก์ และหมายเหตุ
- ดูผลประเมินนิสิต 4 ด้าน พร้อมจำนวนคำตอบ หัวข้อที่สนใจ และข้อเสนอแนะ
- ดูผลประเมินบริษัทเป็นความคิดเห็น 3 ด้าน ผ่านรายละเอียดกิจกรรม
- หน้าจอเล็กแสดงทะเบียนเป็นการ์ด และมีปุ่มบันทึกในส่วนท้าย dialog

## แหล่งอ้างอิงและข้อมูลทดลอง

ตรวจหัวข้อไฟล์ใน Downloads แบบอ่านอย่างเดียว:

| แหล่งข้อมูล | ข้อมูลที่นำมาออกแบบหน้าจอ |
| --- | --- |
| ตารางกิจกรรม CEDT FridayAct 2566-2569.xlsx / ชีตสรุป | ปี ภาค ครั้ง วันที่ เวลา บริษัท หัวข้อ รายละเอียด ศาสตร์ รูปแบบ ห้อง จำนวนรับ จอง มาจริง คะแนนสรุป และลิงก์ |
| ประเมินฝั่งนิสิต.xlsx | คะแนนเนื้อหา การถ่ายทอด การนำไปใช้ และภาพรวม รวมถึงหัวข้อที่สนใจ/ข้อเสนอแนะ |
| ประเมินฝั่งบริษัท.xlsx | ความคิดเห็นเกี่ยวกับกิจกรรม หัวข้อที่อยากแบ่งปัน และสิ่งที่อยากให้หลักสูตรพัฒนา |
| Dummy ตารางกิจกรรม CEDT FridayAct.xlsx | ตรวจโครงสร้างหัวตารางเทียบกับไฟล์หลัก |

ข้อมูลในหน้าใหม่ **สร้างสมมติทั้งหมด** ไม่ได้คัดลอกชื่อบริษัทจริง ข้อมูลผู้ติดต่อ
นิสิต หรือคำตอบประเมินจริงจากไฟล์เหล่านี้ ข้อมูลทดลองมี 11 กิจกรรม: 7 กิจกรรมใน
2569/1 และอย่างละ 1 กิจกรรมใน 2568/1, 2568/2, 2567/1, 2566/1
เทอมอื่นแสดงสถานะไม่มีข้อมูล ไม่มีการย้อนมาใช้ข้อมูลเทอมเริ่มต้น

ชื่อสถานะ `scheduled/completed/cancelled` เป็นแบบจำลองสำหรับหน้าทดลองนี้
ไม่ได้แปลว่าต้นทางบันทึกสถานะเหล่านี้ไว้แล้ว และไม่ได้ตัดสินว่าจัดแล้วจากวันที่เพียงอย่างเดียว

## ความหมายของตัวเลข

| ตัวเลข | วิธีคำนวณ |
| --- | --- |
| กิจกรรมทั้งหมด | ทุกสถานะตามตัวกรองในเทอมที่เลือก พร้อมจำนวนแยกแต่ละสถานะ |
| บริษัทที่มาจัดแล้ว | นับ `companyId` ไม่ซ้ำ เฉพาะกิจกรรมสถานะจัดแล้ว |
| ผู้เข้าร่วมจริง | ผลรวมจำนวนมาจริงของกิจกรรมจัดแล้ว หน่วยคน-ครั้ง ไม่ใช่นิสิตไม่ซ้ำคน |
| จำนวนรับ / จอง / มาจริง | เก็บแยกกัน ค่าว่างคือไม่ทราบ 0 คือไม่มีคน และมาจริงอาจเกินจำนวนรับ |
| ความพึงพอใจนิสิต | ค่าเฉลี่ยคำตอบที่มีคะแนนด้านภาพรวมของกิจกรรมจัดแล้ว คะแนนเต็ม 5 |
| ผลประเมินรายด้าน | ค่าเฉลี่ยจากแต่ละคำตอบที่มีคะแนนในด้านนั้น ไม่เฉลี่ยค่าเฉลี่ยกิจกรรมซ้ำ และไม่นับ null เป็น 0 |
| คะแนนสรุปในตารางต้นทาง | แสดงแยกใน dialog ไม่รวมกับค่าเฉลี่ยคำตอบ |
| ผลประเมินบริษัท | ข้อความ 3 ด้าน ไม่มีคะแนนตัวเลขหรือค่าเฉลี่ยร่วมกับนิสิต |
| ต้องติดตาม | รอจัดแต่วัน/เวลา/สถานที่ไม่ครบ หรือจัดแล้วแต่ขาดจำนวนมาจริง/แบบประเมินฝั่งใดฝั่งหนึ่ง ไม่รวมยกเลิก |

เมื่อกิจกรรมจัดแล้วทั้งหมดไม่มีจำนวนมาจริง จะแสดงว่าไม่มีข้อมูล ไม่แสดงยอด 0
หากมีข้อมูลบางกิจกรรม จะแสดงผลรวมเฉพาะที่ทราบ พร้อมจำนวนกิจกรรมที่ยังขาด

## ขอบเขตการบันทึก

ใช้ `useDashboardDataset` และ key `nextlink.friday.activities.v1` ผ่านการแยกบัญชี
โมดูล ปี และเทอมของระบบเดิม รองรับ undo, reset, conflict และ recovery
การแก้ข้อมูลกิจกรรมไม่แทนที่บริษัท เทอม คะแนนต้นทาง หรือคำตอบประเมิน
ตัวตรวจข้อมูลปฏิเสธจำนวนติดลบ/ทศนิยม วันเวลาไม่ถูกต้อง สถานะไม่รองรับ และลิงก์ที่ไม่ใช่ http/https

ยังไม่มี API/Database/import จริง และไม่ซิงก์ข้ามเครื่อง รายการบริษัทในโมดูลนี้
ใช้รหัสสมมติภายใน ยังไม่ได้เชื่อมบริษัท MOU หรือ LINE จริง การใช้ข้อมูลจริงต้อง
ผ่าน API ที่ตรวจสิทธิ์ server-side พร้อมจับคู่บริษัท กิจกรรม และคำตอบประเมินที่ตรวจทานแล้ว

## การตรวจบนเครื่อง

- `npm run build` ผ่าน รวม TypeScript และ route ใหม่
- ESLint ของ Dashboard, routes, browser script และ Friday domain tests ผ่าน
- `npm run check:dashboard`: 53 ข้อผ่าน (เพิ่ม Friday 7 ข้อ)
- `npm run check:dashboard:browser`: 14 กลุ่มผ่าน ใช้ API จำลอง ไม่ใช่ฐานข้อมูลจริง
- Browser checks ครอบคลุมทุกโมดูลในสองธีม จอ 320/390/820 px การบันทึก/รีโหลด
  ตัวกรอง เทอม session แยกบัญชี และความแตกต่างของค่าว่างกับ 0 ใน Friday
- ตรวจด้วยตาบนหน้า local: ภาพรวมเดสก์ท็อป ผลประเมิน การ์ดมือถือ และ dialog แก้ไข
- หลักฐานที่ไม่ commit: `output/friday-activity/` และ `output/playwright/dashboard/`

การตรวจเหล่านี้ไม่ใช่การยืนยัน deployment หรือฐานข้อมูล production
